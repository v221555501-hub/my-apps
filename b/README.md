# B / C 繁體中文網站 APP 原型

開啟 index.html 選擇版本，或分別開啟 b/index.html、c/index.html。建議透過 HTTP 靜態伺服器或 GitHub Pages 使用，以確保本機儲存來源一致。

## GitHub Pages 部署（不需建置）

1. 建立 GitHub 儲存庫，將本資料夾內容上傳到儲存庫根目錄，保留 b/、c/ 結構。
2. 進入 Settings → Pages → Build and deployment，選擇 Deploy from a branch。
3. 選擇 main 分支與 / (root)，儲存並等待 GitHub 部署完成。
4. 網址為 https://帳號.github.io/儲存庫名稱/，B 版在 b/，C 版在 c/。

若要完全獨立部署，將 b/ 或 c/ 內三個檔案放入各自儲存庫根目錄即可。獨立部署時側欄「返回原型選擇」連結指向上一層，可刪除或改為自己的首頁網址。

## 使用

- 新增、編輯、刪除、完成／重新開啟；表單可調整狀態、日期、分類、優先級與備註。
- 搜尋文字、狀態／分類／優先級篩選；點月曆日期篩選，同一日期再點一次取消。
- 月曆支援切換月份；清除篩選可回復目前頁面的全部紀錄。
- C 版可按社區卡片或下拉選單篩選，修繕資料有廠商／負責人及進度備註；會議決議與所有權人會議分開分類，後者以紅色呈現。
- 提醒清單顯示已逾期與未來七天內未完成事項。沒有背景通知或推播。
- 匯出 JSON 備份；匯入相同版本備份會取代目前資料，操作前有確認提示。

## 資料與限制

純 HTML / CSS / JavaScript，無外部套件與 CDN。b/ 和 c/ 各自完整且可獨立運作。根目錄 app.js、shared.css 是共同開發來源，修改後需複製到 b/app.js、c/app.js 與各自 style.css。

資料使用不同 localStorage key 儲存於同一裝置、瀏覽器與網站來源。初次開啟自動載入可編輯示範資料，日期相對於初次開啟日。重新整理保留資料；清除網站資料、無痕模式結束或更換網址／瀏覽器會影響資料存取。儲存不可用時會顯示警告，請手動匯出。

未建置後端、登入、多人權限、跨裝置同步、推播、郵件提醒、附件上傳或正式廠商通訊。本原型不會聯絡廠商。示範姓名與廠商為虛構。請勿在公開部署原型輸入敏感住戶資料。
